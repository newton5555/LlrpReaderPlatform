01 / OPERATOR USER MANUAL

LLRP Reader Studio user manual

This guide covers the current desktop and cross-platform workflow: add a reader, inspect its capabilities, configure a safe inventory, perform Tag Access and review persisted run records. Hardware-specific behavior always follows the reader's capability response.

Quick start and environment

  1. Download the matching package from Downloads.
  2. For Windows WPF, extract LlrpReaderPlatform-v2.0.3-win-x64.zip and launch LlrpReaderPlatform.exe.
  3. Use a physical reader or start the Virtual Device Manager for a local TCP test endpoint.
  4. Allow the app to create its local SQLite data store.

01. Discover and connect a reader

Open Data Sources and either run local-network discovery or enter the reader address and LLRP port manually.

  • Probe results populate model, firmware and identity fields according to the device response.
  • Keep the source profile only after checking the address, port and detected protocol information.
  • The default LLRP port is commonly 5084, but the configured device endpoint is authoritative.

02. Inspect capabilities and configure settings

After connection, the settings editor maps the reader's declared power, sensitivity, RF-mode and antenna tables into selectable values.

  • Only values returned by the device should be treated as valid for that model.
  • Antennas can be enabled and tuned independently when the capability model exposes those controls.
  • Impinj controls such as Search Mode, Low Duty Cycle or FastID appear only when the extension/profile path supports them.
Validation: a setting visible in another reader profile is not automatically valid for this device.

03. Start inventory and monitor reports

Start inventory from the main action bar to view aggregated EPC, antenna, RSSI, count and timestamp data. Stop the run explicitly when the field operation is complete.

  • Attached TID/User data is shown only when the reader and selected inventory settings return it.
  • Pause and clear are local view operations; they do not imply a physical RF pause unless the corresponding reader command is sent.
  • For long runs, use the persisted InventoryRun record to review the outcome later.

04. Target of Interest (TOI)

Maintain a local TOI list in SQLite with EPC, name, category and highlight metadata. Matching tags receive the TOI projection in live and historical views.

05. Tag Memory Access

Select a tag and memory bank, then issue the supported Gen2 operation through the short-operation lease.

  • Read and write use word pointers and word counts appropriate to the selected bank.
  • Lock and kill require the corresponding passwords and device/tag support.
  • Review the returned operation result before assuming the tag state changed.

06. GPIO triggers and relay control

GPIO actions are capability-driven. The platform does not assume a universal four-input/four-output layout or a fixed five-second timing.

  • Inputs and outputs appear only when the reader exposes the relevant capability or integration path.
  • Trigger modes, debounce and pulse timing depend on the device and adapter.
  • Physical trigger behavior remains a hardware-acceptance concern; validate wiring and firmware on the target reader.

07. Inventory Runs history

Each start/stop interval creates an InventoryRun record with timestamps, counts and an explicit stop/disconnect reason.

  • Review run metadata and captured tag details from the history view.
  • The current application does not provide Excel or CSV export.

08. Troubleshooting

  • Cannot connect: check address, port, firewall and whether another client owns the reader session.
  • Settings rejected: refresh capabilities and choose values from the device-provided tables.
  • No tags: verify antenna enablement, tag placement, RF mode, reader power and the selected inventory report settings.
  • GPIO unavailable: confirm the reader model/firmware exposes the required capability; the UI cannot add unsupported hardware.
  • Virtual endpoint: confirm the manager is running and that the client uses the same loopback address and port.
