SYSTEM ARCHITECTURE & DESIGN

Architecture Overview & Engineering Design

LlrpReaderPlatform centralizes LLRP protocol orchestration, hardware lifecycle, device capability modeling, semantic parameter compilation, and vendor extensions in a shared services layer, keeping UI consumers completely decoupled and lightweight.

1. Core Engineering Goals

  • UI Decoupling: ViewModels and Razor components never hold direct TCP sockets or orchestrate raw LLRP messages; they only consume platform services and immutable DTOs.
  • Deterministic Concurrency: An LLRP reader TCP socket is an exclusive resource. All commands pass through an internal Session Gate to serialize execution and prevent race conditions.
  • Two-Stage Capability Discovery: Standard LLRP probing discovers baseline identity first, followed by dynamic Impinj/Zebra extension attachment during capability synchronization.
  • Closed-Loop Parameter Verification: Applying settings strictly follows Query → Edit → Validate → Apply → Query Readback, never mistaking local memory cache for actual reader hardware state.

3. Session Gate & Concurrency Serialization

In the LLRP protocol, an active reader TCP connection is strictly single-tenant. To avoid protocol deadlocks and message interleaving, the platform enforces single-owner leasing:

Session Gate Invariant: Each ReaderHandle manages exactly one active ReaderSession. All short-lived requests (Probe, Settings Query, Settings Apply, Tag Access, GPO switches) queue through the Session Gate.

When a reader is running an active Inventory session, the TCP socket is held exclusively by the ROSpec lease. Any concurrent attempt to modify settings or perform Tag Access returns an explicit PlatformErrorCode.ReaderBusy error without interrupting or restarting the inventory session.

4. Lifecycle: Short-Lived Probing vs Long Inventory Lease

  • Short-Lived Probing (Probe & Activate): During reader discovery or activation, the platform establishes a brief TCP handshake, sends GET_READER_CAPABILITIES, snapshots the capabilities, and disconnects immediately. The UI reflects "Capabilities Synced".
  • Long Inventory Lease: When Start is triggered, an exclusive session is created, compiling and activating the ROSpec for real-time RO_ACCESS_REPORT streaming. Clicking Stop flushes in-flight reports, saves the run snapshot, and safely closes the connection.

5. Settings Compilation Engine

Supported via ISettingsExtensionContributor, settings are structured as a semantic tree (SemanticId / GroupKey / InstanceKey). UI controls render generic editors without hardcoding vendor branches, while Impinj/Zebra contributors inject proprietary parameters.

6. Offline Persistence & Layered Logging

  • SQLite Database: Located at %LocalAppData%\LlrpReaderPlatform\llrp-reader-platform.db with automatic EF Core schema migrations.
  • Layered Logs: ui-*.log (user actions), platform-*.log (services/leases), sdk-*.log (raw LLRP binary wire packets).
  • Inventory Snapshots: Supports Off, FinalSnapshot, and RawReports (full JSONL report stream) recording modes.
