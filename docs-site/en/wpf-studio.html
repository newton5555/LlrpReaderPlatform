PRIMARY WINDOWS CLIENT

LLRP Reader Studio (Windows WPF)

src/LlrpReaderPlatform.App.Wpf is the primary Windows desktop surface for field operations, debugging and true-device acceptance. It controls physical readers and TCP virtual readers through the platform service boundary.

Positioning and runtime behavior

The WPF client uses MVVM and shared platform services. Reader sessions are protected by ReaderHandle leases so concurrent UI actions do not blindly issue conflicting commands.

  • Windows package: v2.0.3 is delivered as a self-contained x64 directory archive with LlrpReaderPlatform.exe.
  • Long-run resource control: bounded aggregation and controlled subscriptions reduce unbounded report backlog risk.
  • Acceptance surface: Impinj R420 and standard LLRP evidence is tracked separately from software/virtual tests.

01. Inventory view

The view projects RO_ACCESS_REPORT messages into aggregated EPC, capability-driven antenna, peak RSSI, seen count, timestamp and optional TID/User fields.

EPC                 : 96-bit / 128-bit hexadecimal EPC
Antenna ID          : reader-declared antenna port
Peak RSSI (dBm)     : reported peak signal strength
Seen Count           : aggregated observations
Last Seen (UTC)      : last report timestamp
TID / User Memory    : attached data when enabled
Impinj Serialized TID: vendor field when supported
Impinj RF Phase      : vendor field when supported

Pause, clear and antenna/RSSI filtering are local view actions. Raw tag events can be written asynchronously to a local .jsonl audit log; the client does not currently provide CSV export.

02. Tag Memory Access

Use the guided C1G2 operation flow to target a tag by EPC or TID selector and read/write Reserved, EPC, TID or User memory when supported. Lock and kill require the relevant access/kill passwords.

Lease: Tag Access takes a short reader-session lease and releases it after the operation, so it does not own the long-running inventory channel.

03. Target of Interest

TOI metadata is stored in SQLite and projected into live and historical views. Give an EPC a business name, category and highlight color for focused tracking.

04. Inventory Runs

Each start-to-stop interval is saved as an InventoryRun entity with timestamps, unique/total counts and an explicit stop reason.

  • Review historical run metadata and tag summaries.
  • The current client does not export reports as CSV or Excel.

05. Reader Settings Editor

The editor reads TransmitPowerTable, ReceiveSensitivityTable and UHFRFModeTable from the connected reader. Controls are populated from those capabilities rather than from a fixed model-independent list.

  • Adjust supported antenna ports independently.
  • Apply standard RF and inventory settings through the service lease.
  • Expose Impinj options only when the matching extension/profile is active.

06. Data sources and discovery

Add a reader by discovery or by host/port, then probe it to populate the available identity and capability information. A virtual endpoint can be entered as 127.0.0.1:5084.

07. GPIO triggers and relay control

GPIO controls are shown according to the reader capability and adapter. There is no universal fixed input/output count or pulse duration; physical trigger wiring and firmware behavior require target-device acceptance.
