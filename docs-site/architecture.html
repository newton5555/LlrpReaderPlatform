04 / CORE ARCHITECTURE & PLATFORM SERVICES

平台服务体系与架构设计

LlrpReaderPlatform 不是第二个 LLRP SDK，而是一套建立在 LLRPCSharp 之上的应用服务平台。负责协调读写器生命周期、会话租约排队、配置编译投影、本地数据持久化以及多 UI 消费者的解耦。

分层设计与严格的依赖方向

为了保证核心业务逻辑的高内聚与可测试性，平台代码遵循严格的单向依赖原则： 

UI Composition Roots (WPF / MAUI / Linux)
      │
      ▼
LlrpReaderPlatform.Contracts (纯 DTO / 接口 / 错误码 - 零外部依赖)
      │
      ▼
LlrpReaderPlatform.Services (生命周期 / 租约门禁 / 盘存聚合 / 投影)
      │
      ├─► LlrpReaderPlatform.Infrastructure (SQLite / Zeroconf / 日志)
      ├─► LlrpReaderPlatform.Extensions.Impinj & Zebra (厂商模块)
      └─► LlrpSdk NuGet (LLRPCSharp 协议驱动)
架构单测守护： 仓库内包含专门的架构约束测试（Architecture Tests），强制禁止在 Contracts 中引用 WPF、SDK 报文或厂商专属类型，杜绝底层依赖泄漏。

读写器句柄与会话租约门禁 (Reader Ownership & Concurrency)

RFID 读写器通常只支持单 TCP 连接与单会话状态机。为了防止 UI 界面在盘存过程中意外发送冲突指令导致设备报错，平台设计了 ReaderHandle 租约机制：

SHORT LEASE

短期操作租约

探测 (Probe)、配置下发 (ApplySettings)、Tag Access 与 GPIO 申请瞬时租约，执行后立即释放。

LONG LEASE

长期盘存独占

盘点从 StartInventory 到 Stop 独占会话通道，期间所有报告由此通道持续上报。

DETERMINISTIC

确定性状态保护

发生租约竞争时，平台确定性返回 ReaderBusy 错误码，绝不发生状态竞争或盲目重启。

插件化厂商扩展架构 (Impinj & Zebra)

平台在连接读写器后会自动解析设备企业号 (Enterprise Number / IANA)：

  • IANA 25882 (Impinj)：自动激活 Extensions.Impinj 模块，加载双向搜寻模式 (Search Mode)、低占空比、Serialized TID 与 RF 相位角上报。
  • IANA 161 (Zebra)：自动激活 Extensions.Zebra 模块，提供射频电源与自主模式扩展支持。
  • 标准读写器：未匹配到厂商扩展时，平滑回退至标准通用 LLRP 驱动路径。

统一错误码体系 (Platform Error Codes)

平台定义了面向应用层的稳定错误码，屏蔽底层 Socket 异常与复杂的 LLRP 状态码：

  • ReaderNotFound：指定的读写器句柄不存在或已被移除。
  • ReaderBusy：读写器当前正在执行独占盘存或关键操作，租约已被占用。
  • ConnectionFailed：TCP 传输无法建立，网络超时或端口被占用。
  • ProtocolError：读写器返回了非预期的 LLRP 错误响应。
  • CapabilityMismatch：下发的参数超出该型号读写器支持的物理能力范围。

物理硬件兼容性与验收基线

平台的兼容性声明严格以真机验收记录为准（非 Mock 或单元测试）：

  • Impinj Speedway Revolution R420 (LLRP 1.0.1)：生产级验收通过。连接、能力探测、标准与 Impinj 专有配置、盘点、FastID、相位、User 区读写、GPI 状态与 GPO 控制均具备完整实机验收证据。
  • 标准 LLRP 1.0.1 / 1.1 读写器：基础功能验收通过。连接、能力探测与配置回写已验证。
  • Zebra FX9600：实验性模块。已验证连接与设备身份，高级特性待进一步标定。
