SYSTEM ARCHITECTURE & DESIGN

平台架构总览与工程设计

LlrpReaderPlatform 致力于将 LLRP 协议底层编排、硬件生命周期、设备能力模型、参数语义编译与厂商专有扩展完整沉淀于共享服务层， 实现上层 UI 框架（WPF、MAUI Blazor、GTK4）的彻底轻量化与高内聚解耦。

1. 核心设计目标

  • UI 绝对解耦：UI 消费层（View / ViewModel / Razor Component）不直接持有 Reader TCP 连接，不编排 SDK 协议报文，仅消费平台公开契约与服务。
  • 高可靠并发控制：物理读写器是独占的 TCP 资源，所有协议通信必须通过串行化门禁（Session Gate），杜绝多线程竞争引发的协议状态机错乱。
  • 两阶段设备感知：标准 LLRP 协议先行探测基础身份，二次握手无缝挂载 Impinj / Zebra 厂商扩展能力，保证不同品牌硬件的自适应接入。
  • 配置下发闭环保障：配置修改严禁使用本地缓存冒充硬件状态，必须实施 Query → 编辑 → Validate → Apply → Query 回读 完整闭环校验。

2. 分层解耦体系

解决方案采用严格单向依赖架构，杜绝反向依赖与循环引用：

[ UI Consumers: WPF / MAUI Blazor / Linux GTK4 ] (Composition Root)
                      │
                      ▼
         [ LlrpReaderPlatform.Services ] ───► [ LlrpReaderPlatform.Contracts ]
           (生命周期编排 / 设置编译 / 盘存租约)       (纯净 DTO / 错误码 / 服务接口)
                      │                                    ▲
          ┌───────────┴───────────┐                        │
          ▼                       ▼                        │
[ Infrastructure ]      [ Extensions.Impinj / Zebra ] ─────┘
 (SQLite / mDNS / 日志)   (厂商私有参数编译 / 专有事件扩展)
          │                       │
          └───────────┬───────────┘
                      ▼
              [ LLRPCSharp SDK ]
LlrpReaderPlatform.Contracts跨 UI、跨实现的纯领域契约，定义只读模型、枚举、事件与接口。零依赖，不引用 WPF、SDK 或第三方 UI 库。
LlrpReaderPlatform.ServicesReader 生命周期管理、会话租约分配、设置编译聚合、标签流分发。只依赖 Contracts 与 SDK 适配层。
LlrpReaderPlatform.InfrastructureEF Core SQLite 数据库存储、mDNS / Zeroconf 发现、分层日志记录器等底层具体实现。
LlrpReaderPlatform.Extensions.*厂商可插拔扩展（如 Impinj FastID / Phase / Doppler / Search Mode / 4路 GPIO）。不污染通用契约。

3. 会话独占与并发门禁 (Session Gate)

在 LLRP 协议中，一个物理 Reader 端口在同一时刻仅允许一个活动的 TCP 连接。为防止 UI 多次触发操作引发通信冲突，平台引入了严格的独占门禁机制：

Session Gate 串行化约束： 每个 ReaderHandle 对应唯一的活动 ReaderSession。所有发往读写器的短命令（如 Probe、Query Settings、Apply Settings、Tag Read/Write、GPO 触发）均通过内部 Session Gate 排队串行执行。

当某个 Reader 处于长期盘存（Inventory）状态时，连接被 ROSpec 独占。此时若尝试下发设备设置或执行 Tag Access，平台服务将立即返回确定性的 PlatformErrorCode.ReaderBusy 错误，绝不隐式停止、中断或重启正在运行的寻卡租约。

4. 短连接与长盘存租约模型

平台严格区分两种生命周期模型，保证网络连接的高效与健壮：

  • 短连接探测 (Probe & Activate)： 在 Data Sources 中添加或刷新 Reader 时，平台建立短暂 TCP 握手，执行 GET_READER_CAPABILITIES 获取型号、固件与频率表，匹配厂商扩展后立即断开 TCP 连接，保留内存能力快照。UI 显示为“已同步能力”。
  • 长连接寻卡租约 (Inventory Lease)： 用户点击 Start 寻卡时，平台建立持续长连接，下发编译后的 ADD_ROSPEC 与 ENABLE_ROSPEC，开启实时 RO_ACCESS_REPORT 报告流；点击 Stop 后，平稳排空缓冲区、保存快照并主动断开连接。

5. 设置模型与编译引擎

不同厂商的 LLRP 读写器在天线功率、跳频表、Gen2 会话、专有过滤参数上存在巨大差异。平台通过 ISettingsExtensionContributor 机制实现了优雅的编译扩展：

  1. 语义化参数树：设置项以 SemanticId / GroupKey / InstanceKey 组织，UI 仅根据语义渲染通用编辑器（如滑块、下拉列表、复选框），不包含任何厂商代码分支。
  2. 动态扩展注入：当设备识别为 Impinj 时，ImpinjSettingsExtensionContributor 自动将 FastID、SearchMode、RF Phase 等专有参数并入配置树。
  3. 闭环回读校验：保存设置时执行 SET_READER_CONFIG，随后立即执行 GET_READER_CONFIG 回读；只有回读值与下发值一致，才判定为保存成功。

6. 数据持久化与分层日志

平台内建轻量、鲁棒的数据管理机制，满足现场免维护与事后追溯需求：

  • SQLite 本地存储：数据库位于 %LocalAppData%\LlrpReaderPlatform\llrp-reader-platform.db，首次启动通过 EF Core 迁移闸门自动初始化，管理设备 Profile、Tag Lists 与历史 Run 记录。
  • 三层隔离日志体系：
    • ui-*.log：记录 UI 交互、ViewModel 命令分发与用户操作。
    • platform-*.log：记录服务生命周期、Session Gate 状态与持久化事务。
    • sdk-*.log：记录原始 LLRP 协议二进制报文、TCP 链路事件与解码诊断。
  • 盘存审计模式：提供 Off（仅内存聚合）、FinalSnapshot（停止时输出统计快照）与 RawReports（输出全量原始 JSONL 报告流水）三级记录模式。

7. 虚拟设备与测试边界

为支持无硬件离线开发与自动化测试，平台确立了清晰的虚拟化双轨边界：

进程内替身 (In-Process Mock)通过环境变量 LLRP_VIRTUAL_SCENARIO 驱动，用于单元测试与快速 UI 逻辑验证。
独立 TCP 虚拟设备 (Virtual Device Manager)独立的 LlrpVirtualDeviceStudio.exe 工具，监听物理 5084 端口，模拟完整的真实 TCP/LLRP 报文通信与标签射频池。
