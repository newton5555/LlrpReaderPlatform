CORE CAPABILITIES

平台核心服务与技术特征

读写器会话租约门禁 (Leased Concurrency) 短租约 (配置/读写) 与长盘点隔离，确定性返回 ReaderBusy 避免竞争 → EF Core SQLite 本地结构化持久化 自动持久化已注册设备、配置方案、TOI 关注库与历史盘存 Runs → 能力驱动配置编辑器 (Capability-Driven) 根据物理硬件真实声明的功率与模式表动态生成界面，杜绝非法下发 → TOI 目标卡关注库与实时投影 为关键资产自定义标签与颜色，在所有盘存流与历史报告中高亮标记 → GPIO 传感器联动与继电器控制 实时监控 GPI 输入信号电平，支持光电触发自动寻卡与 GPO 报警 → 插件化厂商扩展架构 (Impinj / Zebra) 低侵入性适配 Impinj FastID / Phase / Search Mode 与 Zebra 自主模式 →

LIFECYCLE WORKFLOW

标准读写器操作调度生命周期

01 Discovery / Probe 通过 mDNS 自动发现或输入 IP 建立临时会话，探测硬件能力
02 Register & Activate 保存设备至 SQLite 本地数据库并激活为主工作读写器
03 Capability Settings 基于物理能力表编辑 RF 功率、模式与过滤，下发并保存为预设
04 Start Inventory 申请独占 Session 租约，启动持续盘点并流式消费标签
05 Runs & Snapshot 停止盘点并持久化本次 Run 的完整汇总与停止原因

PLATFORM PHILOSOPHY

设计哲学：UI 独立与严格的架构边界

LlrpReaderPlatform 保证 UI 仅仅是消费端。所有的 ViewModels 和 Razor 组件均不直接操作 TCP Socket 或构建底层 LLRP 报文。统一通过 LlrpReaderPlatform.Services 申请短期/长期租约，确保了无论是多天线工业大屏监控、Android 手持机巡检，还是自动化测试脚本，均能享受完全一致的高可靠性保障。
