## 已执行步骤

1. 使用 WPF 添加/激活设备，验证 Probe 和能力同步；
2. 打开设备设置 Tab1，读取当前标准配置；
3. 将 `Report Every N Tags` 从 1 改为 2，保存并刷新读取为 2，再恢复为 1；
4. 在 Tab2 将 GPO1 从 OFF 切换 ON，再切回 OFF；
5. 在 Tab1 将 Impinj GPI1 debounce 从 20 ms 改为 250 ms，保存并刷新读取为 250 ms，再恢复为 20 ms；
6. 在寻卡页运行约 5 秒，执行 Stop，确认同一 Inventory 生命周期完成停止并断开；
7. 使用测试 EPC `300833B2DDD9014000000000` 执行 Tag Memory 读取请求，确认请求经过平台服务和 SDK 适配层；设备返回超时。
8. 追加使用 `LlrpSdk 1.2.0 + UseImpinj()` 的一次性 SDK 现场探测，读取到天线 `1,2,3,4`、`UponNTagsOrEndOfAiSpec`、`ReportEveryNTags=1`；持续 15 秒仍为 0 条 TagReport，随后 Stop/Disconnect 成功。
9. 在现场出现真实标签后，使用新平台 `ReaderManager` 运行 10 秒 Inventory：收到 1533 条 `TagObserved`，聚合 8 个唯一 EPC，自动停止后状态为 `Disconnected`。
10. 使用 EPC `E201E24F3E0B0E1CFAAF8700` 通过新平台 Tag Access 读取 TID Bank（偏移 0、6 words、天线 1），成功返回 `E201E24F3E0B0E1C00008600`。
11. 使用新平台 `ReaderManager` 查询 R420 能力画像：FastID/Phase 出现在 Tab1，Doppler 不出现；将 FastID/Phase 设为 `True` 后 Apply/Query 均回读 `True`，运行 10 秒 Inventory 未发现现场标签；随后重新 Query 生成新能力版本 Draft，将两项恢复为 `False` 并回读成功。
12. 使用新平台 Tag Access 对真实 EPC 的 User Bank 0 偏移 1 word 执行原值读取（`0000`）、临时写入 `A55A`、回读、写回原值和最终回读，五步均成功。
13. 使用新平台读取 GPI 状态，返回 4 路端口，均为未配置/低电平；GPO1 的 ON→OFF 证据仍来自 WPF Tab2。
14. 开启 FastID/Phase 后使用新平台运行 10 秒 Inventory，聚合 6 个 EPC；首个扩展报告含 `Tid=E201E2E42C090E1C86002021`、`impinj.serializedTid=E201E2E42C090E1C86002021`、`impinj.rfPhaseAngle=524`、`impinj.peakRssi=-5150`；随后关闭两项并回读为 `False`。
15. 修复天线覆盖逻辑后，以 `InventorySpec.Antennas=[1]` 开启 FastID/Phase 运行 Inventory，成功聚合 10 个标签；首个报告含 `Tid=E2801171200013CEADD309A0`、`impinj.serializedTid=E2801171200013CEADD309A0`、`impinj.rfPhaseAngle=1016`、`impinj.peakRssi=-7600`；随后关闭两项并回读为 `False`。
16. 使用当前平台 Services（临时 TagLog 目录，不改项目数据库）运行 3 秒、天线 1 的 Inventory，自动停止并记录 `StopReason=Duration`；运行记录统计 5 个唯一标签、12 次读取，JSONL 文件存在且包含 12 行，首行长度 455 字符。
17. 使用同一真实 EPC 通过平台 Tag Access 只读验证各 Memory Bank：EPC Bank（偏移 1、6 words）返回 `3000E201E24F3E0B0E1CFAAF`，User Bank（偏移 0、1 word）返回 `0000`，Reserved Bank（偏移 0、2 words）返回 `00000000`；本步骤不修改标签。

## 已知限制

- 早期 5 秒/15 秒探测没有标签，未观察到 TagReport；后续真实标签已补齐标准 TagReport 和 TID 读取证据；
- 已补齐 EPC/TID/User/Reserved 四个 Memory Bank 的真实读取；尚未验证 User 以外 Memory Bank 的写入，以及写入期间 Inventory 长租约冲突的真实设备表现；
- FastID/Phase、Search Mode、Low Duty、Fixed Frequency 的真机 Apply/回读已完成；FastID/Phase 扩展 TagReport 已观察到上述字段，但字段单位/厂商语义仍按原始字符串保留；Doppler 已由 R420 固件/SDK 能力画像判定为未验证并从布局隐藏，不得下发；
- 尚未完成第二台标准 LLRP Reader、多 Reader 并行和现场断网/设备重启恢复验收。

## 结论

当前 R420 可声明为：L1 已验证；L2 标准 Inventory、TagReport 字段和生命周期已验证；L3 标准设置、GPO、GPI 状态查询、四个 Memory Bank 读取和 User Bank 写入恢复已验证，GPI 事件/触发行为、其它 Memory Bank 写入及 Inventory 冲突仍待补测；L4 的 GPI debounce、FastID/Phase、Search Mode、Low Duty、固定频率设置 Apply/回读以及 FastID/Phase 扩展报告已验证，Doppler 在当前固件上明确隐藏。不得据此声明 R420 已达到完整 L1～L4。
